# Browser runtime audit — 12 October 2026

The audit covers the recovered version 1.6 scripts, all eight rooms, the browser runtime, input, storage, and player menus. Original recovered GML is preserved; changes are recorded in `patches/` or the JavaScript runtime. All recovered entries parse, every referenced function is implemented, and generated output passes JavaScript syntax checks.

## World saves and cheats

Three named IndexedDB slots store all visited room instances and local state, global progress, camera, layers, alarms, simulation timing, random state, and cheat toggles. S/L statistics saves and Menu do not overwrite these slots. World loading does not write the original statistics file.

Worlds round-trip exactly in all eight rooms and resume a deterministic 90-frame simulation. Checks cover death, an open computer, sleep, a running petrol shift, destroyed enemies, collected pickups, and new adventures. Repository checks cover independent slots, import/export, failed writes preserving the previous slot, and rejection of invalid imports before changing a running world. Files are limited to 8 MB with bounded object counts and nesting.

Cheats supply invulnerability, unlimited ammunition, unlimited slow motion, resource gifts, healing/revival, and weapon unlocks. Toggles restore with a world and reset on a new adventure.

## Realistic-face easter egg follow-up

A realistic face moon drifts across the original menu occasionally. One click switches Daniel and all four menu runners to a transparent photographic head with a neck that reaches into the collar. While active, the moon remains on-screen for one-click deactivation; it leaves after deactivation and returns on a later pass. The preference survives new games and reloads without changing world snapshots or collision masks. Head anchors follow each idle, running, jumping, and death frame. Six additional checks cover moon hit testing and room guards, periodic flight and persistent deactivation, appearance persistence, unchanged simulation state, player/menu-only rendering, neck alignment, and smooth photographic sampling. Artwork loads once on demand; the optional white-flash mask is bounded to 210 × 280 pixels.

The supplied MP3 loops only on the active easter egg menu, using one lazy, reusable HTML audio element. Mute and pause preserve position; deactivation and room changes stop and rewind the clip. Blocked playback does not retry every frame, and obsolete playback rejections cannot block a newer resume request. Three additional tests cover these transitions and interruption handling. Browser verification confirmed the decoded 54.775-second clip plays, pauses on mute/pause, stops at time zero on deactivation and menu exit, and restarts on re-entry with no runtime errors.

## Final static scan — October 12, 2026

Reviewed the hand-written browser modules, the GML translator and generated conditions, save validation and storage, rendering/collision bounds, input ownership, room transitions, audio lifecycle, local server paths, and asset packaging. The scan found and fixed four classes of bug:

| Finding | Previous behavior | Correction and evidence |
| --- | --- | --- |
| GameMaker numeric booleans | JavaScript treated `noone` (`-4`) as true. Negated collision queries therefore prevented enemy guns from firing even with clear sight. | The translator now applies GameMaker numeric boolean conversion to conditions, logical operators, and negation, while preserving short-circuit evaluation. A regression exercises clear, obstructed, and cleared sight lines, plus the numeric threshold. |
| Incomplete or incorrectly typed world saves | A save could omit gravity direction, supply text as money/physics, or override validated health through room-local variables. Loading could yield non-finite velocity without recording a runtime error. | Required physics/rendering fields and known statistics are validated before mutation. Room-local names share the same allowlist used by capture. A regression verifies malformed saves leave the current world unchanged. |
| Synchronous IndexedDB failure | If an action threw after queuing the world write, the transaction could still commit that write without matching metadata. | Aborting the transaction on a synchronous exception preserves both records together. The regression simulates a metadata cloning failure after the first write. |
| Input or sound before startup completes | Enter/Space could start an Engine with no loaded room, and unmuting before Play could enable initial ambience. | Startup and keyboard routing require a loaded room; sound stays disabled until Play. Browser verification blocked the first atlas, pressed Enter, and observed no uncaught startup exception. The block was removed and a normal reload verified pre-play mute/unmute, movement, jumping, and menu entry. |

GameMaker's documented rule treats real numbers at or below 0.5 as false. See the official [data types](https://manual.gamemaker.io/monthly/en/GameMaker_Language/GML_Overview/Data_Types.htm) and [instance keywords](https://manual.gamemaker.io/monthly/en/GameMaker_Language/GML_Overview/Instance_Keywords.htm) references. Enemy gunfire is now enabled when the original scripts allow it, which can change combat difficulty from the previous broken behavior.

Firing eligibility now visits the existing indexes for the five interactive object types instead of sweeping every instance each frame. Contextual hints use indexed first-object lookups instead of allocating arrays just to read their first item. A regression checks that visible interactions still suppress firing, while hidden and removed targets release it.

One sequential seeded benchmark before and after this scan measured:

| --- | --- | --- |

An asset/reference scan resolved all event and room-creation references for the eight rooms, 169 objects, 685 compiled events, 33 original sounds, textures, fonts, and easter egg assets. ## Touch controls and launch recovery — October 12, 2026

The virtual gamepad uses independent input sources for each finger and shares the original keyboard/mouse router. Movement, jumping/revival, aiming and firing, weapon switching, interaction, closing/kissing, slow motion, menu selection, and story/ending continuation are covered. Automatic/always-show/hide preferences are independent of keyboard bindings and saves. Pause, dialog opening, rotation, room changes, and cancelled pointers release virtual inputs. The renderer still uses one fixed-resolution canvas; no extra game images or rendering surfaces were added.

Browser checks used touch emulation and actual 320 × 640, 390 × 844, and 844 × 390 viewports. They verified stick movement, touch settings and persistence, native fullscreen with usable dialogs, weapon switching, aimed grenade use and release, and face activation through the menu moon. A simulated two-pointer DOM sequence verified that releasing Jump preserves movement and cancelling the movement pointer clears its input. Native multi-touch dispatch is unavailable in the in-app browser; physical iOS/Android testing remains unverified. Short-screen dialog headers now scroll with their content instead of covering buttons. The expanded toolbar has a separate strip so it does not cover the game's health, money, and ammunition.

Fast vertical movement sweeps the intervening walls, preventing thin-platform tunneling after an extreme launch. The initial wall-edge recovery was replaced by bounded local recovery in the follow-up below. World-anchored computer/job/quest choices stop the player while open so launch momentum cannot carry their camera away. Ordinary movement uses the recovered collision code. Regressions exercise both high downward and upward impulses, adjoining stair tiles, and closing a job menu after a launch.

The recovered `gml_GlobalScript_KillPlayer.gml` removes one heart per call. `Object1` collision events for `oEnemy` and `oEnemyBig` call it each frame without a cooldown; the enemy-bullet event also destroys that bullet. This behavior is retained. The regression verifies one bullet removes one heart and sustained enemy contact removes one heart per frame, rather than introducing a new invulnerability period.

`oDanielbaby`, spawned by the companion's Q interaction, now shares the photographic face mode with Daniel and the menu runners. Existing idle/run/jump head anchors and the four-pixel collar overlap scale with each miniature's size and facing. Toggling the mode changes appearance without changing masks or simulation state; other characters retain their original faces. Both regression checks and the live companion interaction verified these miniature faces.

The follow-up adds 17 checks, bringing the suite from 73 to 90. The release verifier serves all 56 files correctly under both `/` and `/Adventures-Of-Daniel/`. One sequential seeded simulation run measured Home median/p95 **2.220/3.625 ms**, first level **1.249/1.742 ms**, **12.38 MiB** of managed heap, and zero runtime errors. Browser timing and physical-phone performance are outside these measurements.

## House-ground teleport and audio — October 12, 2026

The previous recovery could snap an embedded player to a distant edge of a large floor. At `(6300, 2740)` beneath the house, it moved Daniel to approximately `(5053.243, 2740)`, a 1,247-pixel jump to the left without cheats or a launcher. Some local edge candidates were blocked by adjacent tiles or rejected by floating-point roundoff. Recovery now searches nearby geometry, includes diagonal candidates, uses a tiny clearance at contact edges, and applies no more than eight pixels of correction per frame. Horizontal candidates are limited to the character's width plus a small margin. In the browser reproduction, Daniel stayed at x=6300 and gradually reached clear ground at y≈2475.543, with a largest correction of eight pixels. Recovery uses saved simulation state rather than private movement history. Regressions cover both gamepad directions, shallow stairs, and deterministic continuation from a mid-recovery world save.

The audio scan found overlapping ambient loops, loop positions resetting on pause/mute, silence on cached-room returns and level resumes, pending `play()` requests reusing a supposedly idle element, stale playback handles, and revival sounds escaping a paused cheat menu. These are corrected. Pending requests reserve their channel, stopped/recycled requests cannot cancel or restart a newer sound, and ended effects release handles. Scene ambience returns once on room/world restoration and revival; death scenes stay silent on resume. Pausing and muting suspend loops, while a room change or the recovered `audio_stop_all()` stops them. Playback rejection and media errors wait for a later gesture; menu music also handles delayed completion and decoder errors without retrying every frame.

Effect allocation is limited to 24 HTML audio elements, with three per sound; lower-priority effects can be replaced while loops remain reserved. Priority handling follows the intent of GameMaker's [audio_play_sound](https://manual.gamemaker.io/monthly/en/GameMaker_Language/GML_Reference/Asset_Management/Audio/audio_play_sound.htm). The optional menu clip remains one separate element. Original Ogg files and the supplied menu MP3 are unchanged. Each of the 33 original sounds now has an MP3 fallback selected by codec support or a rejected Ogg decoder. [WebKit's Safari 18.4 release notes](https://webkit.org/blog/16574/webkit-features-in-safari-18-4/) document the newer Ogg-container support. Fallbacks are generated sequentially with `npm run rebuild:audio` and FFmpeg, rather than decoding the whole sound library in the browser.

Fifteen audio regressions cover duplicate/pending loops, pause/mute position, cached rooms and world restoration, handle cleanup, channel limits and priorities, late resolution/rejection, blocked playback, synchronous exceptions, undefined legacy play results, format selection, paused cheat revival, death/revival, and menu media errors. All 33 MP3 fallbacks fully decode without FFmpeg errors; their largest duration difference from the packaged Ogg sounds is 0.021 seconds. Browser checks verified one active ambient loop, pause/resume and mute/unmute around the 30-second mark without rewinding, real MP3 playback, menu music stopping and rewinding on exit, and cached-room ambience returning once. Physical iOS/Android testing remains unverified.

The combined suite has 108 passing checks. All 90 deployment files are verified at both URL layouts (14.27 MiB total). One sequential seeded simulation benchmark measured Home median/p95 **2.248/2.949 ms**, first level **1.207/1.672 ms**, **17.22 MiB** of managed heap, and zero runtime errors. These measurements exclude browser rendering and media memory.


## Off-map falls, original controls, and iPad combat work — October 12, 2026

A live player or death body could fall indefinitely outside the terrain, and the death script only enables revival after landing. The runtime now checks below the lowest actual wall bottom plus 256 pixels, including floors below the room's nominal height. A living player returns to a validated landing at the last grounded position; old saves or missing support fall back to the bed or original room spawn. Health, inventory, quests, surviving enemies, and money are preserved. A fallen body returns to ground and runs the existing landing/revival sequence without a second death penalty. High upward launches, active room transitions, and sleep/dialog control are preserved. Grounded recovery coordinates belong to the serialized player state, with validation for imported values, so mid-fall world continuation stays deterministic.

The stock object's recovered `Visible` flag is true, and its layers have no recovered parent visibility attribute. `specialbutton` contains the stock-balance display, while the buy button is created on `buttons`. Closing/back scripts park the buy button at `Object1.y - 1000`, normally beyond the camera. The port now explicitly hides and disables its interactions whenever the stocks screen is absent, keeping the same object and original price alarms. Reopening the screen reuses it rather than creating an overlapping buy controller. Browser checks verified $100 purchases, closing visibility, and a running price alarm.

The recovered gun Begin Step switches to `oGun59` on F; the launcher fires while F is held and primary fire returns to `oGun`. The previous toggle-only interpretation is corrected. A tap fires once immediately, holding repeats with the original cooldown, and primary fire returns to one owned gun. A launcher without an acquired gun can still use primary fire. Existing rebinding preferences keep their action ID; labels, hints, and the virtual **Grenade** button describe the restored behavior. Quick touch Fire/Grenade taps released before a simulation frame also work. Holding F without an acquired launcher produces one empty-weapon sound per press. Harmless recovered gameplay quirks and original sustained-contact damage are retained.

The virtual movement stick now aims along walking direction while there is no independent aim/fire action. The aiming stick or held Fire/Grenade takes priority; a direct canvas aim remains authoritative until another movement-stick gesture. Real browser dragging changed Daniel's facing from left to right while moving right, with no held keys after release. Tests cover both directions, backward aiming while moving, and camera-relative aiming.

Enemy collision queries reuse geometry derived from current positions, masks, scales, and angles. Transform changes and hypothetical collision probes invalidate or bypass it; the cache is a WeakMap and adds no private simulation history to saves. Event phases skip objects with no corresponding handlers, and stationary objects avoid zero-velocity native-physics calculations. A seeded 180-frame comparison produced exactly matching world snapshots in all eight rooms before/after these optimizations. Idle audio channels are reused across sound types before allocating new elements, preserving pending requests, active loop reservation, priorities, and the existing caps. A sequential all-sound regression needs only one effect element plus the ambient element.

One desktop browser comparison in an 844×390 viewport with all 25 original enemies alive measured median simulation **0.70 → 0.50 ms**, p95 **1.10 → 0.80 ms**, and zero runtime errors. These are local measurements, not physical iPad frame-rate results. The latest sequential Node benchmark measured Home median/p95 **1.480/2.013 ms**, first level **0.845/1.389 ms**, and the 25-enemy room **0.732/1.870 ms**, with **17.08 MiB** managed heap and zero runtime errors. The combined suite has 119 passing checks; all 90 deployment files pass verification at both URL layouts (14.27 MiB). ## Movement/aim teleports, mobile grenades, and bounded rendering — October 12, 2026

A reproducible combat teleport came from the recovered player's collision search, rather than a distant-ground rescue. With fractional recoil and a slightly rotated precise mask, the requested horizontal endpoint collided with the floor while one-pixel probes missed the thin contact. The search continued until a distant obstacle: the minimal fixture moved x=6530.040 to 6257.639, a 272-pixel jump; walking/firing traces also produced 1,858- and 2,973-pixel jumps. Each player collision search now stops after the attempted movement has been used. The original one-pixel resolution and horizontal bounce remain. The minimal fixture still fails with the previous compiled player event and passes with the patch; the browser changed x by only 0.598 pixels. Six additional 800-frame traces exercise three locations with both keyboard/mouse and the virtual gamepad, repeatedly turning, firing, moving, and jumping. All 4,800 frames stay within 32 pixels of movement per frame, with no runtime errors.

A separate pointer bug was confirmed with the original six-pixel camera shake. Home has two camera instances; world mouse coordinates were recalculated after the first camera's Step. A click one pixel outside the petrol entrance moved inside it during the same tick and teleported Daniel about 7,070 pixels. World coordinates are now sampled once per simulation tick, and a canvas press retains the world point displayed when it was pressed. New virtual/synthetic coordinates override obsolete press samples. Mouse events, recovered mouse variables, and firing eligibility all use the same point; held aiming is sampled again next tick, and room/input resets clear the sample. The regression also verifies intentional entry still works.

The player requested death instead of automatic return to ground. The void guard now invokes the normal death flow once after Daniel's entire mask leaves the actual terrain bounds by 256 pixels horizontally or falls below every floor by 256 pixels. Bounds include the original ground extending past the nominal room width and height. A void body becomes immediately revivable in place without requiring a landing surface. Invulnerability does not prevent this environmental death, and the normal $200 death penalty applies once; inventory, quests, selected weapon, and surviving enemies persist. Explicit Revive returns to the original bed or room spawn with eight hearts. The hidden player stays stationary while awaiting revival, so waiting in the void does not create runaway physics or invalidate a world save. Eight regressions cover launches at both edges, below-map falls, all four gameplay rooms, invulnerability, repeated guards, extended original terrain, high flights over the map, deterministic saves, dialog/transition guards, and 600 ticks of waiting before revival.

The virtual Grenade button is now a selection control. Selecting it consumes no ammunition and changes the right stick to aiming and throwing; the separate Throw button uses the last aimed direction. Gun selects gun firing again. Changing selection while a firing finger is held requires it to lift or return to center before firing resumes. Pause, death, room/context changes, and cancelled input clear the selection and release controls. Physical F still fires grenades immediately and primary click returns to an acquired gun. Live browser checks confirmed no consumption on selection, aimed grenade firing, gun firing after selection, and no held input after release.

Hints now select the nearest actionable door or other interaction before generic weapon instructions. Opening ranges match the recovered/patched door events (80/100 pixels); closing uses 120 pixels. Bed hints use the actual 100-pixel click range. Destroyed or hidden objects are ignored, and hints reflect live open/closed state, current key bindings, unavailable bindings, touch controls, and grenade selection. Browser Use/Close actions switched the corresponding prompts correctly. Immersive mobile/fullscreen hints use larger text on a dark backing so they remain readable over the scenery.

Rendering uses an opaque canvas and one background fill, reuses up to 2,048 draw-command slots, and retains stable depth order when depths and command count are unchanged. Animation, current visibility/culling, and all Draw/GUI event side effects still execute every draw. Texture-page indexes are precomputed; geometry/text calculations avoid temporary arrays. The shared font, RGB tint, and white-mask cache retains at most 64 entries and 8 MiB of canvas pixels, and eviction releases canvas backing storage. Nine tests cover pixel/alpha composition, cache limits/eviction, text layout, depth changes, culling, and off-screen Draw side effects. A JavaScript draw-setup benchmark excluding raster/GPU work measured Home 0.877→0.770 ms and the third room 0.379→0.315 ms; the first level was essentially unchanged. These are component measurements, not physical iPad frame-rate results.

Timer activity uses a derived 12-slot mask while preserving original instance and slot order. Events can still start later slots/instances during the same phase; creation, destruction, replacement, GML writes, `alarm_set`, and saved worlds retain their behavior. Fresh runtime arrays and privately cloned snapshots use the fast path. Supplied/replaced arrays are conservatively rescanned so retained raw JavaScript aliases remain effective. No mask or cache is serialized. Fourteen tests exercise these cases. A native-instance Home timer-phase benchmark measured 0.099→0.028 ms per pass; complete simulation timings varied between runs, so no fixed overall speedup is claimed.
